# 录制中识别说话人的建设方案

更新日期：2026-11-07。本文描述后续方案，**当前版本尚未实现实时说话人区分**。现有说话人按钮运行的是 sherpa-onnx 的会后完整音频分析：Pyannote 分段、3D-Speaker ERes2Net 声纹与聚类，结果使用 `Transcript.speaker_turns` 保存，已有姓名记忆仅在清晰发言足够长时使用。

## 能否复用现有方案

可以复用已下载的分段和声纹模型、16 kHz 音频、时间轴、说话人展示与会后复核，但不能简单地对每个短音频块独立执行会后 `OfflineSpeakerDiarization` 并把结果当作同一人的固定编号：每个窗口的聚类编号是局部的，跨窗口会变化，短语音和重叠发言也容易误判。项目目前把系统声和麦克风混成音轨送 ASR，不能假定每条来源只含一个人。

[sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/c-api/html/speaker_diarization.html)公开的是离线说话人分离接口，同时提供[声纹提取与检索接口](https://github.com/k2-fsa/sherpa-onnx/blob/master/sherpa-onnx/c-api/cxx-api.h)。[在线分离研究](https://arxiv.org/abs/2109.06483)采用滚动音频窗口、局部分段和增量聚类；[diart](https://github.com/juanmc2005/diart)可作流程参考。两者不证明当前这套模型或旧 i5 已达到实时性能，也不应把其 Python 服务作为项目新增的必需常驻进程。

## 建议实现

1. 在现有音频观察通道旁增加独立的本地说话人工作队列，保留录制时钟和暂停边界。使用有界滚动缓冲和非阻塞发送；队列满或模型跟不上时跳过分析、标记未确定，绝不阻塞录音、录屏或 ASR。默认关闭，由用户在录制前启用。
2. 在固定窗口内按实际模型输入长度做说话人分段，保留相邻窗口的重叠区域；对足够长、未重叠的语音计算现有 3D-Speaker 向量。只用清晰发言更新该场的说话人中心，对短语音、噪声、重叠和接近阈值的结果标记「未确定」或「交替 / 重叠」。窗口长度、步长和阈值由实测选定，不能承诺毫秒级或完全准确。
3. 增量聚类需要维护跨窗口、跨暂停的稳定编号；采用相似度阈值与最佳 / 次佳差距判定，保留最近窗口允许后续修正，避免每个窗口重新编号。说话人编号是本场临时标签，不自动等同于姓名；已保存姓名的匹配继续受现有声纹记忆授权和样本质量约束。
4. 独立表示实时暂定标签和会后分析结果：按时间范围关联 ASR 句段，句段跨多人的情况保留「交替或重叠」，不把整句强行归给一个人。将暂定结果和修订号持久化，但不覆盖用户编辑、姓名和历史纪要；会后完整分析可另存或在用户明确操作后替换暂定结果。
5. 可进一步保留系统声与麦克风各自的来源信息，辅助区分渠道；同一渠道仍可能多人同时说话、回声和串音也可能跨渠道，不能把渠道直接当作真实身份。任何声音分离或回声消除另行验证。

## 验收与边界

- 使用经授权的多人普通话、中英混说、远场、重叠、短发言和设备回声样本，人工标注说话人时间区间；比较 DER、错分 / 漏分、编号变化率、未确定比例和从发言到显示标签的 P95 延迟。合成声音只能检查流程和时间轴。
- 在同一台第一代 i5 Windows 上固定录屏参数，比较关闭 / 开启说话人识别时的 OpenCap / DWM CPU、内存、ASR 实时落后、鼠标响应、音画丢失与 30 分钟稳定性。连续积压时需提示并降级为未确定，不能用不完整标签冒充实时完成。
- 先实现可关闭的本地实验模式，验证后再评估默认策略；会后分析仍是当前可用方案。转录、录音和声纹都留在本机，任何未来云端处理仍需用户明确选择。
