# OpenCap v3.0 RC1

应用与安装包内部版本为 **3.0.0**，本标签 `v3.0-rc.1` 是发布候选，GitHub Release 会标记为 prerelease，不覆盖 v2.0 的“最新版本”。

## 本版重点

- 新会议默认以开始时间命名，不再带 `OpenCap_` 前缀；受管理会议可连同目录、媒体、逐字稿标题和资产清单一起改名，操作有日志可恢复。
- 会议身份、资产 ID、识别运行 ID 与配置快照；每次识别记录模型、运行时、音轨、媒体指纹、标点和复核配置。
- 内置音视频回放：媒体与逐字稿双栏、点击句段跳播、选区循环、倍速/音量、波形缓存、跟随播放；快速 seek 使用 generation 隔离旧缓冲。录制期间禁止回放，避免被系统 loopback 录入。
- 实时转录继续使用本机 CPU 小模型；新配置默认开启逐句复核，轻量实时负责低延迟出字，所选文件模型在停顿后校正整句。已有设置保留原选择。
- 录制/文件转录中的增量 AI 纪要（DeepSeek Responses 等文本服务），来源可跳回原音；纪要正文先保存，Word 导出失败可单独重试。
- 会议库紧凑/普通密度、分页、全文与两字中文检索、组合筛选；SQLite 索引可重建。
- 说话人：会后本机分析保留版本与人工命名；在线说话人为默认关闭的实验路径，需自行选择可信原生库和固定模型。
- 修复：AI 服务正常响应带 `"error": null` 时被误判为失败；会议库在滚动页内列表零高；新录制被误报“转写数据未能读取”；自动说话人过度切分时提示填写已知人数。

## 验证范围

本机 macOS arm64 已通过：格式检查、严格 Clippy、149 项自动测试（11 项需外部媒体/密钥的测试按需忽略）、Release 构建、真实 20 分钟录音的文件识别与导出、真实媒体播放/seek/循环/波形、真实媒体改名，以及 DeepSeek 真实纪要（合成文本、3 分钟摘录和完整 118 段转写）。真实录音的自动说话人出现 32 组过度切分，指定 4 人模式得到 4 组；没有人工标注，不能据此宣称说话人准确率。

未验证：Windows/Linux 实机、低配 Windows 性能、120 分钟超长会议、真实麦克风/系统声的实时录制质量、在线说话人验收、语义检索（需额外 embedding 模型）。本 RC 的云端三端构建与安装包由本标签触发的 GitHub Actions 校验。

## 安装包

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Windows | `OpenCap-3.0.0-windows-x64.zip` | 完整解压后运行 `OpenCap/opencap.exe` |
| macOS Apple Silicon | `OpenCap-3.0.0-macos-arm64.zip` | 最低系统版本以本次 Release 验证信息为准 |
| macOS Intel | `OpenCap-3.0.0-macos-x64.zip` | 最低系统版本以本次 Release 验证信息为准 |
| Linux / 统信 UOS | `OpenCap-3.0.0-linux-x64.deb` 或 `OpenCap-3.0.0-linux-x64.tar.gz` | x86_64、glibc 2.28+；便携包运行 `OpenCap/AppRun` |

安装包不包含用户录音、文档、配置、密钥或语音模型。第三方依赖与许可证见 [THIRD_PARTY.md](https://github.com/NOBB2333/meeting_summary/blob/v3.0-rc.1/THIRD_PARTY.md)。
