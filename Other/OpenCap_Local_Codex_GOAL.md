## 2 必须实现的最终体验

- 新会议目录和文件默认以开始时间命名，没有 OpenCap_ 前缀。
- 重命名会议会统一修改受管理文件夹、媒体、转写、纪要、历史版本、笔记和关联信息；重启仍能打开。
- 软件内部播放音频和视频。默认左侧媒体/内容、右侧逐字稿，播放到哪里高亮到哪里。
- 点击时间或句段跳播；拖选文字先保留正常选择，随后可以播放或循环所选句段。
- 用户手动滚动不被强制拉回；可以恢复跟随。
- 可查看原始转写、复核稿和当次实际识别配置，支持按原配置另存重转。
- 录制过程中持续产生文字和匿名说话人标签，允许短时间修订；说话人编号不因为音频分块而跳变。
- 录制和文件转录过程中都有增量 AI 纪要，来源可点击回听；结束后有可靠的最终整理。
- 会议列表紧凑，可搜索、筛选，超过 100 条仍全部可访问。后续启用可选语义检索。
- 下载、识别、复核和保存状态真实；有需要的取消、重试和阶段提示。
- “降低占用”不再顺带关闭预览与实时文字；预览布局保持稳定。
- 修正失效设备假显示默认、电平高位停留和静音不归零等问题。

## 3 模型选型指令

不要把“模型数减少”当唯一目标，也不要在没有样本对比时替换所有现有模型。

先做两条共用接口的 POC：

1. 保留 Zipformer/SenseVoice 等当前 ASR，独立接入 Nemotron 3 Diarization，通过 NeMo-Speech.cpp C ABI 持续输入 PCM。
2. 使用 Nemotron 3.5 ASR Streaming 0.6B + 同一 diarizer，对比中文准确率、首字延迟、稳定 speaker 延迟、时间戳和资源。

运行时参考提交 e790e463b2913cff9f989a3df224c587f14b4c5c；实施时核查最新状态，固定实际使用版本、模型 SHA-256 和打包依赖。其 Windows 文本 normalization 限制、八人容量、CPU/Metal/Vulkan 实测状态都要如实记录。

VibeVoice-ASR-Streaming 是确实存在的一体化 ASR + speaker 候选，但发布权重主要面向约八分钟，原始输出无精确时间戳，不能直接作为长会议默认。若做实验，必须验证跨窗口身份连续性、对齐和硬件内存。不要混用 TTS、离线 VibeVoice、BitNet 的性能结论。

Fun-ASR-Nano 的新端侧路线可作中文备选，注意 checkpoint 和 runtime 的时间戳能力差异。候选模型只通过统一后端接口接入，不各建一套 UI。

评测同一批真实或授权样本，记录文字、speaker、时间戳、延迟、内存和录屏同时运行的表现。没有实测数据时明确未验证，保持当前可用路径。

## 4 不可违反的数据和时序规则

1. meeting_id、asset_id、run_id 稳定；名称和路径可变。实体改名使用可恢复操作日志，处理 Windows 文件占用和播放器句柄。
2. 旧 JSON 向后兼容，未知字段及历史稿保留。外部原音与管理资产区分，不能根据同名前缀误改外部文件。
3. 播放、转写、说话人和检索共用原媒体时间；录制暂停移除后不能再按墙钟补回。
4. 播放高亮依据设备实际/预计输出时间，不依据已解码或已入队采样。seek 必须清理全部旧缓冲并隔离旧 generation。
5. 只有真实且映射到当前文字版本的时间戳才用于逐词高亮。无词对齐时按句段，不按字数比例伪造精度。
6. 音源不等于说话人，匿名编号不等于真实姓名。身份状态和重叠状态分开；重叠活动也不代表每个词已经正确归属。
7. 实时 speaker 接口必须保存跨块状态。反复调用完整离线分析不能冒充已经完成在线 diarization。
8. 句段改字、speaker 改名、用户编辑、模型迟到结果都带 revision/generation 校验，不覆盖用户锁定内容。
9. 停止后的在线任务有界排空，未知 speaker 不无限阻塞最终保存；会后全场精修是独立任务。
10. 纪要本体先保存，Word/Markdown 等导出独立失败与重试。
11. 不使用一个全局 busy 无理由禁止所有不相关操作；录制链路不等待 AI、speaker 或索引。
12. 所有历史识别配置来自当时快照。旧数据缺失时显示未记录，不用当前设置补造。
13. 录制中回放可能进入系统 loopback。首版按主计划 D03 明确处理，不静默污染会议、不宣称截图排除能排除音频。
14. 不自动上传实际会议音频；远程能力由软件中的明确选择启用。API key 不进入快照、日志和版本库。

## 5 按批次推进

按主计划 B0–B6 执行，并行只用于互不冲突的模块：

- B0：核对工作区、开发版隔离、建立样本和复现。
- B1：稳定身份与运行快照，修现有按钮、进度、设备、电平、列表和预设缺陷。
- B2：实体改名与内置播放器形成可用纵向链路，同时重做核心布局。
- B3：在线说话人接口、两条原生 POC、稳定编号和后端评测。
- B4：会中/文件转录增量纪要、来源回放、最终整理。
- B5：全文与语义检索、词级对齐和精细片段回听。
- B6：平台边界、性能和发布包验收；GPU 深度优化按证据推进。

在代码层完成有意义的一批后验证并记录结果，再进入下一批。不要为了凑测试覆盖率写只镜像实现的测试；优先验证重命名恢复、时间轴、seek、迟到回包、身份稳定和任务取消这些真实风险。
